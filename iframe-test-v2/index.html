Co odwzorowuje ten test?
  • Układ zmierzony na game-on.kfc.pl/pl/gamehub: od 992 px boczne menu ma 215 px, a iframe zaczyna się na wysokości 69 px i ma wysokość calc(100vh - 65px). Różnica 4 px i przewijanie rodzica są celowe.
  • Poniżej 992 px menu znika, iframe zaczyna się na wysokości 104 px i ma wysokość calc(100vh - 104px). Używane jest vh, nie dvh, jak w referencji. Zachowana jest też minimalna szerokość strony 350 px i cienki scrollbar rodzica.
  • Ramka nie ma atrybutów sandbox, allow ani allowfullscreen. Rodzic nie przechwytuje dotyku, przewijania ani komunikatów gry.
  • Domyślnie ładowany jest lokalny hub. Wybierz grę w nagłówku lub podaj adres w tym oknie. Możesz też otworzyć ?src=../gaming-challenge/index.html.
  • Uruchom serwer HTTP z głównego katalogu projektu (np. Live Server w VS Code) i otwórz /iframe-test-v2/. Zmiana rozmiaru okna lub orientacji nie przeładowuje ramki.
  • Produkcja osadza hub z innej domeny. Aby testować to samo ograniczenie origin, podaj adres lokalnej gry z innego portu lub domeny. Ten sam origin nie odwzorowuje ograniczeń pamięci i uprawnień cross-origin.
  • Sprawdzaj dotyk, paski przeglądarki i orientację na fizycznym telefonie. Sam rozmiar okna nie emuluje telefonu. HTTPS i polityki serwera również wpływają na działanie gier.
  • To autorska makieta układu, nie kopia strony. Nie odtwarza cookies, kont, API ani dodatkowych nagłówków HTTP produkcji; nie omija CORS, CSP ani X-Frame-Options.

Otwarto plik z dysku. Użyj serwera HTTP, aby prawidłowo ładować gry i ich zasoby.
